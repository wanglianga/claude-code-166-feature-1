# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：**家属申请 → 家庭医生六要素评估 → 可解释排班 → 护士上门执行（体征/压疮/换药/导尿/血糖血压/用药/家属签字）→ 上门未遇处理（到达定位/电话/等待时长/门口照片留证 → 家属补充说明 → 卫生院减免·空跑费·扣次·调整下次；患者临时送医则暂停家庭病床、医生复评后恢复）→ 医生调处方/复诊/转诊（远程复核）→ 护理+耗材+冷链+空跑费统一账单（医保/自费一单清）→ 医保合规审查 → 全链可还原**。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts；Spring Boot 3.3 + Spring Security/JWT + JPA；PostgreSQL 15；Docker Compose 一键启动。

## 一、快速启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

- 前端：http://localhost:8088
- 后端 API：http://localhost:8080
- Swagger UI（OpenAPI 3 文档）：http://localhost:8080/swagger-ui.html
- PostgreSQL：localhost:5432（homebed/homebed123）

首次启动后端会自动建表并写入演示数据（9 个测试账号、5 名患者、申请/评估/计划/已完成巡诊/医嘱/风险事件/一张含合规初审结果的演示账单，以及 3 条不同状态的“上门未遇”工单：待家属说明 / 已减免关闭 / 患者临时送医病床暂停待复评）。

停止：`docker compose down`（保留数据加 `-v` 之外默认保留卷；清空数据用 `docker compose down -v`）。

## 二、本地开发启动

### 1. 数据库（PostgreSQL 15）

```sql
CREATE USER homebed WITH PASSWORD 'homebed123';
CREATE DATABASE homebed OWNER homebed;
```

### 2. 后端（Java 17 + Maven）

```bash
cd backend
mvn spring-boot:run
# 或 mvn package && java -jar target/homebed-backend.jar
```

如数据库不在本机默认端口，用环境变量覆盖：`DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD/UPLOAD_DIR/JWT_SECRET`。

### 3. 前端（Node 18+）

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173 ，已配置 /api、/uploads 代理到 8080
npm run build    # 生产构建输出到 dist/
```

## 四、建议的业务验证路径

1. **家属** 登录 → “建床申请”为老人提交申请（勾选护理需求）。
2. **家庭医生** 登录 → 对申请评估：病情/距离（可按坐标自动测算）/照护人/医保资格/护理项目频次/风险等级 → 批准建床或驳回。
3. **管理者** → “巡诊计划排班”选择批准单 → **智能排班**：查看三名护士在技能匹配、本周负荷、路线聚集、半径红线上的打分，以及“为什么是她、为什么不是别人”的可解释说明与基层约束权衡（系统自动生成 4 周上门任务）。
4. **护士** → “上门巡诊”对待办任务**签到上门** → 填写体征、压疮/换药/导尿/用药记录、勾选护理收费项、领用耗材（冷链药品登记交接温度）、上传现场照片、采集**家属手写签字**后提交。
   - 可验证异常：上报“家属不在家/耗材缺货/患者住院”等，任务自动挂起；管理者在“巡诊异常”中改期/改派恢复。
   - 可验证风险：血压 ≥180/110、血氧 <92%、冷链温度越界等会**自动生成风险事件**。
5. **上门未遇处理**（“上门未遇处理”菜单，护士/家属/管理者/财务/医生按角色协同）：
   - **护士**按计划到家但家属未开门 → 在“上门巡诊”点**上门未遇**，固化四项证据：**到达定位、电话拨打记录（联系人/结果/通话时长）、门口等待时长、门口照片**；登记后任务挂起。原因选“患者临时急诊/送医”时，家庭病床与巡诊计划**立即自动暂停**。
   - 系统先开放**家属补充说明**（临时急诊/手机没电/地址变更/忘记预约，可上传急诊凭证），**空跑费生成前必须经过说明环节**。
   - **卫生院（管理者/财务）审核**决定：**减免**、**计空跑费**（金额默认取收费目录 `QT001`，可调）、**扣除一次服务**、**调整/顺延下一次巡诊**，或**暂停家庭病床**；审核时可同时改约。
   - 患者临时送医导致病床暂停的，**家庭医生**在工单中填写重新评估结论后**恢复病床与巡诊**（可指定恢复后首次上门时间）；病床暂停期间费用决定可先行记录，但恢复只能走医生复评。
   - 审核确认的**空跑费**由财务按账期生成统一账单时自动计入（自费项目，不走医保），出账后回写“已计入账单”防重复收费；家属也能在本菜单查看本人工单并提交说明。
6. **家庭医生** 在巡诊记录中**下达医嘱**（调整处方/复诊/转诊）→ 用 `doctor2` 登录“医嘱与远程复核”完成**另一名医生远程复核**。
7. **财务** → “统一账单”按账期生成：护理服务、耗材领用、冷链药品、**审核确认的上门未遇空跑费**合并为一单，自动拆分医保报销与家属自费；同来源已出账不重复计入。
8. **家属** 打开账单逐行核对（每行可回溯到巡诊记录与出库流水，空跑费行可回溯到未遇工单的定位/电话/照片证据）→ 确认，或点“对收费有疑问”发起**收费质疑**；财务可对照“服务全链还原”答复并剔除重算。
9. **医保经办** → “医保合规审查”：查看自动初审命中规则（R1 重复收费、R2 超频次、R3 无家属签字、R4 医保资格存疑、R5 冷链温度缺失、R6 目录变化按快照结算、R7 照片证据缺失），给出复核结论后财务结算。
10. **收费/医保目录**（财务）对目录项执行“目录变更”：旧版本失效、新版本生效，历史账单不受影响（R6 会提示按出账快照还原）；空跑费目录项 `QT001` 也在此维护。
11. **管理者看板**：巡诊负荷与超时、上门半径分布与超半径患者、异常类型、风险分布、耗材消耗 Top 与缺货预警、金额概览。
12. **服务全链还原**：选择任一建床申请，查看申请→评估→排班→每次上门（签到/体征/照片/耗材/异常/家属签字/未遇证据与审核）→账单→合规→风险的完整时间线证据。

### 演示数据中预置的冲突素材

- 患者李长顺同一天两次换药（晚间敷料渗湿补换）：合规初审自动命中 **R1 重复收费/超每日限次**，可由医保经办结合家属签字与照片判定“情况属实准予报销”——体现系统是**可解释提示**而非机械拒付。
- 一支门冬胰岛素领用**未登记冷链温度** → 命中 **R5**；登记温度越界则自动生成冷链风险事件。
- 患者孙桂英住在大岭村山后（约 6km，超出 5km 半径）且有 HIGH 风险与待处理血氧风险，排班解释中给出“同片区拼单、雨雪改期、家属须在场”的安排理由。
- **上门未遇预置三例**：① 患者李长顺昨日上门无人应答（两通电话未接、等待 25 分钟、门口照片），**待家属提交说明**，可演示完整“说明→审核→空跑费入账单/减免/扣次/改约”；② 患者孙桂英家属“手机没电”，卫生院核实后**减免关闭**；③ 患者马桂兰**临时送医**，家庭病床与巡诊计划已暂停，用 `doctor` 登录可演示“医生复评→恢复病床与巡诊”。

## 五、实际执行过的验证（本环境）

- `mvn clean package`：后端编译打包通过（Java 17）。
- 后端连接本地 PostgreSQL 15 真实启动，JPA 自动建表、演示数据初始化成功（含统一账单自动生成与合规初审）。
- 执行端到端冒烟脚本（13 个场景全部通过）：7 个角色登录、医生评估批准、可解释排班生成 12 次任务与候选评分、看板 KPI、护士待办、统一账单金额拆分（总额 392.00 / 医保 289.40 / 自费 102.60）、合规初审命中 R1×3+R5、家属确认、医保复核结算、服务链 20 节点时间线、护士完成上门后血压危急值自动生成 HIGH 风险、转诊医嘱经第二位医生远程复核、医保目录变更发版。
- **上门未遇功能（本次新增）在本机 PostgreSQL 15 + Spring Boot 实跑验证，两组共 27 项断言全部通过**：
  - 主流程 19 项：护士登记未遇（定位/电话/等待/门口照片）生成工单并挂起任务、巡诊详情回填工单；家属提交补充说明（临时急诊/手机没电等）；卫生院审核“计空跑费 30 元 + 改约”后任务恢复排班；财务按账期出账时空跑费作为**自费行**进入统一账单（总额/自费=30、医保=0，来源 `EMPTY_RUN`/类目 `EMPTY_RUN_FEE`），并回写工单 `billed=true` 防重复；送医患者家庭病床 `SUSPENDED`、计划 `PAUSED`，家庭医生复评后恢复 `APPROVED/ACTIVE` 并重新安排上门；急诊属实审核减免不收费；家属仅见本人工单。
  - 边界 8 项：不传金额时默认取收费目录 `QT001`（¥30）；护士越权审核被拒（业务码 403），财务可审核“扣除一次服务且不收费”；同一巡诊重复登记被拒；缺到达定位/电话记录/门口照片/等待时长被拒；病床暂停期间登记费用减免决定后状态仍保持 `BED_PAUSED`，随后医生复评才能恢复。
  - “服务全链还原”时间线新增 **上门未遇 / 家属说明 / 病床暂停 / 未遇审核 / 复评恢复** 节点并带门口照片证据；Swagger UI 200，`/v3/api-docs` 含 5 个 `/api/no-show` 接口。
  - 预置演示账单金额仍为 总额 392.00 / 医保 289.40 / 自费 102.60（空跑费不入该历史账单，避免改动既有演示口径）。
- `npm run build`：前端生产构建通过（新增 `NoShow.vue` 页面）；`npm run dev` 启动后验证页面可访问且经 Vite 代理登录后端成功。
- Docker：已提供多阶段 Dockerfile 与 docker-compose.yml（当前沙箱无 docker 守护进程，未在本机执行镜像构建；部署环境执行 `docker compose up -d --build` 即可）。
