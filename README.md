# 乡镇卫生院家庭病床申请巡诊耗材医保结算平台

面向乡镇卫生院的家庭病床一体化平台：**家属申请 → 家庭医生六要素评估 → 可解释排班 → 护士上门执行（体征/压疮/换药/导尿/血糖血压/用药/家属签字）→ 医生调处方/复诊/转诊（远程复核）→ 护理+耗材+冷链+上门空跑费统一账单（医保/自费一单清）→ 医保合规审查 → 全链可还原**。

**上门未遇（空跑）改约与费用处理**：护士按计划上门但家属未开门时，平台留存**到达定位、电话拨打记录、等待时长、门口照片**；任务置为“上门未遇”，并给家属 24 小时**补充说明**窗口（临时急诊/手机没电/地址变更等，可附佐证）。卫生院审核后决定**减免、保留空跑费、部分减免、扣除一次服务或调整下一次巡诊**；若患者**临时送医**，家庭病床与在管计划自动**暂停**、后续任务挂起，须经家庭医生**重新评估**后才恢复巡诊。核定的空跑费按“上门空跑费（丙类、全额自费）”并入统一账单，只出一次且可回溯。

技术栈：Vue 3 + Vite + Element Plus + Pinia + ECharts；Spring Boot 3.3 + Spring Security/JWT + JPA；PostgreSQL 15；Docker Compose 一键启动。

## 一、快速启动（Docker Compose，推荐）

```bash
docker compose up -d --build
```

- 前端：http://localhost:8088
- 后端 API：http://localhost:8080
- Swagger UI（OpenAPI 3 文档）：http://localhost:8080/swagger-ui.html
- PostgreSQL：localhost:5432（homebed/homebed123）

首次启动后端会自动建表并写入演示数据（9 个测试账号、4 名患者、申请/评估/计划/已完成巡诊/医嘱/风险事件/一张含合规初审结果的演示账单，以及 3 条上门未遇记录——分别演示“家属已说明待审核、说明期过已核定空跑费、患者临时送医已暂停病床待复评”——和 1 张病床暂停单）。

停止：`docker compose down`（保留数据加 `-v` 之外默认保留卷；清空数据用 `docker compose down -v`）。

## 四、建议的业务验证路径

1. **家属** 登录 → “建床申请”为老人提交申请（勾选护理需求）。
2. **家庭医生** 登录 → 对申请评估：病情/距离（可按坐标自动测算）/照护人/医保资格/护理项目频次/风险等级 → 批准建床或驳回。
3. **管理者** → “巡诊计划排班”选择批准单 → **智能排班**：查看三名护士在技能匹配、本周负荷、路线聚集、半径红线上的打分，以及“为什么是她、为什么不是别人”的可解释说明与基层约束权衡（系统自动生成 4 周上门任务）。
4. **护士** → “上门巡诊”对待办任务**签到上门** → 填写体征、压疮/换药/导尿/用药记录、勾选护理收费项、领用耗材（冷链药品登记交接温度）、上传现场照片、采集**家属手写签字**后提交。
   - 可验证异常：上报“家属不在家/耗材缺货/患者住院”等，任务自动挂起；管理者在“巡诊异常”中改期/改派恢复。
   - 可验证风险：血压 ≥180/110、血氧 <92%、冷链温度越界等会**自动生成风险事件**。
5. **家庭医生** 在巡诊记录中**下达医嘱**（调整处方/复诊/转诊）→ 用 `doctor2` 登录“医嘱与远程复核”完成**另一名医生远程复核**。
6. **财务** → “统一账单”按账期生成：护理服务、耗材领用、冷链药品合并为一单，自动拆分医保报销与家属自费；同来源已出账不重复计入。
7. **家属** 打开账单逐行核对（每行可回溯到巡诊记录与出库流水）→ 确认，或点“对收费有疑问”发起**收费质疑**；财务可对照“服务全链还原”答复并剔除重算。
8. **医保经办** → “医保合规审查”：查看自动初审命中规则（R1 重复收费、R2 超频次、R3 无家属签字、R4 医保资格存疑、R5 冷链温度缺失、R6 目录变化按快照结算、R7 照片证据缺失），给出复核结论后财务结算。
9. **收费/医保目录**（财务）对目录项执行“目录变更”：旧版本失效、新版本生效，历史账单不受影响（R6 会提示按出账快照还原）。
10. **管理者看板**：巡诊负荷与超时、上门半径分布与超半径患者、异常类型、风险分布、耗材消耗 Top 与缺货预警、金额概览。
11. **服务全链还原**：选择任一建床申请，查看申请→评估→排班→每次上门（签到/体征/照片/耗材/异常/未遇/医嘱/家属签字）→病床暂停/复评/恢复→账单→合规→风险的完整时间线证据。
12. **上门未遇改约与费用**（“上门巡诊”护士端登记 + “上门未遇改约”集中处理页）：
    - **护士**在待上门/上门中任务点“**登记未遇**”：选择原因（敲门无人应答/家属临时外出/患者临时送医/地址变更/电话联系不上），填写**到达定位**（地址+GPS）、**等待时长**、逐条**电话拨打记录**（号码/是否接通/通话秒数）、上传**门口照片**；若“家属提前未请假”可据实勾选。
    - 勾选“**患者临时送医**”并填写送医情况后提交：任务置“上门未遇”，家庭病床自动变为“**暂停巡诊**”、在管计划与后续任务挂起。
    - **家属**在“上门未遇改约”页对本人记录点“**补充说明**”（临时急诊/手机没电/地址变更等 + 佐证材料 + 期望处理）；说明期（默认 24 小时）内卫生院**不能**核定收费/扣次。
    - **管理者/财务**点“**审核处理**”：① 减免（不收费不扣次）② 保留空跑费（按目录标准 ¥30）③ 部分减免（金额不得高于标准费）④ 扣除一次服务 ⑤ 调整下一次巡诊（指定新时间，系统改最近一条后续任务）。
    - 患者送医后，由 **家庭医生**在“病床暂停与复评”页**重新评估**（病情/出院情况、建议首次上门时间），再点“**复评恢复**”，建床回到“批准建床”、计划恢复执行。
    - 财务“按账期生成账单”时，核定收费的未遇记录自动生成“**上门空跑费**”明细（丙类、医保 0、全额自费），已出账不重复计入。

### 演示数据中预置的冲突素材

- 患者李长顺同一天两次换药（晚间敷料渗湿补换）：合规初审自动命中 **R1 重复收费/超每日限次**，可由医保经办结合家属签字与照片判定“情况属实准予报销”——体现系统是**可解释提示**而非机械拒付。
- 一支门冬胰岛素领用**未登记冷链温度** → 命中 **R5**；登记温度越界则自动生成冷链风险事件。
- 患者孙桂英住在大岭村山后（约 6km，超出 5km 半径）且有 HIGH 风险与待处理血氧风险，排班解释中给出“同片区拼单、雨雪改期、家属须在场”的安排理由。

## 七、上门未遇功能的数据模型与接口

- 实体：`NoShowRecord`（未遇单：到达定位、经纬度、门口照片 JSON、电话拨打明细 JSON、拨打/接通次数、等待起止与时长、是否提前请假、审核决定/核定金额/扣次/调整后任务/暂停单/是否已出账/说明截止时间）、`FamilyExcuse`（家属补充说明+佐证）、`BedPauseRecord`（病床暂停/复评/恢复全过程）。
- 枚举：`VisitStatus` 新增 `NO_SHOW 上门未遇`、`PAUSED 暂停待复评`；`BedApplyStatus` 新增 `PAUSED 暂停巡诊`；`CatalogCategory`/`BillSourceType` 新增“空跑费”；以及 `NoShowReason`、`FamilyExcuseReason`、`NoShowStatus`、`NoShowDecision`、`BedPauseReason`、`BedPauseStatus`。
- 主要接口（`/api/no-show`）：
  - `POST /visits/{visitId}/register` 护士登记未遇（可联动暂停）
  - `GET /`、`GET /{id}` 未遇列表/证据详情
  - `POST /{id}/excuse` 家属补充说明
  - `POST /{id}/review` 卫生院审核（WAIVE/CHARGE_FEE/PARTIAL_FEE/DEDUCT_SERVICE/ADJUST_NEXT）
  - `GET /pauses`、`POST /pauses`、`POST /pauses/{id}/reevaluate`、`POST /pauses/{id}/resume` 病床暂停/复评/恢复
